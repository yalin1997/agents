# Agent 對外功能：身分與權限要求

依 2026-10-26 使用者要求：目前僅提供 admin 登入，無註冊與會員功能。後續所有 Agent 對外功能都必須驗證身分與權限。

## 發布條件

- 預設拒絕：每個服務端入口先驗證登入身分，再驗證操作與資源權限。前端隱藏控制項、loopback 綁定及已知 task ID 都不能代替授權。
- 僅 admin 可使用工作台；不提供自行註冊、會員帳戶、任意指定角色或透過前端宣稱 admin 的機制。
- 涵蓋所有讀寫及控制：建立／列出／查詢任務、歷史／對話／活動、串流、成果／下載、檔案讀寫、工具與命令、模型設定、停止／重試／待答續接、A2A 委派與 task 操作。每個物件的查詢與變更都要驗證可存取的工作區與操作權限。
- 對外 HTTP、SDK gateway、A2A 與 SSE／WebSocket 等入口都須納入；不能只保護首頁或 POST。公開入口僅允許必要登入頁、登入所需靜態資產與登入操作；Agent Card 若公開只能含無敏感資訊的必要中繼資料，不可暴露受保護資料或繞過操作。
- 正式 admin 密碼由管理員安全初始化，服務端以適當密碼雜湊保存；不得使用原型示範密碼、硬編碼預設密碼、明文密碼或前端比對作為驗證。
- 使用服務端可撤銷及有期限的 session；適當設定 HttpOnly、SameSite 與部署環境的 Secure cookie。cookie 驗證的變更操作需有 CSRF 防護及來源驗證。跨網路部署必須使用 TLS；目前 loopback 限制繼續保留。
- 登出與 session 失效後，服務端拒絕後續請求，撤銷或關閉受保護訂閱／串流。執行中工作是否繼續應由明確產品政策決定；session 失效不可繼續向未登入者傳送結果。
- 未登入回應 401；已登入但無操作／資源權限回應 403，避免洩露敏感資料。登入失敗使用一致提示，加入服務端嘗試次數限制。
- 密碼、session token、模型金鑰不得出現在 URL、一般日誌、事件、成果或前端持久儲存；稽核記錄身分、操作、目標、時間及允許／拒絕結果，但不含密鑰與敏感內容。

## 驗收

1. 未登入直接呼叫每個受保護入口（含列表、下載與串流）均無法讀取資料或產生副作用。
2. 竄改前端身分、角色、task ID、workspace、資源路徑或繞過 UI 直接發請求，服務端仍拒絕不被允許的操作。
3. 正確 admin 登入可操作被允許的範圍；錯誤密碼、失效／撤銷 session、登出後的原 token 均不能操作。
4. 驗證串流初始授權與失效處理、CSRF／來源拒絕、登入速率限制，以及敏感資料不進 log 或瀏覽器持久儲存。
5. 每新增一個對外功能必須把它納入驗證矩陣，不允許新增未受保護的替代入口。

## 現況與界線

`ui-prototype.html` 仍是管理員登入介面的模擬預覽，公開帳密 admin／pi-demo 只適用於虛構資料，不能作為後端驗證。

正式 `pi_deepagent.web` 入口依 [實作規格](ui-implementation-spec.md) 提供 admin 雜湊憑證、服務端 session、CSRF／來源驗證及任務資源權限檢查。詳見 [使用方式與邊界](web-workspace.md)。既有獨立 Python CLI／A2A 沒有由 Web 服務掛載或代理，不代表這些舊入口已加上正式驗證；後續新增或整合仍須符合本文件。
