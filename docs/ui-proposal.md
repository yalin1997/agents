# Pi Workspace — Agent 產品 UI 提案

2026-10-26 · 設計提案 v3 · 本機單人開發工作台

## 產品主張

「描述工作，看見進度，檢視成果。」將目前 CLI 包裝為本機瀏覽器工作台，主要對象是需要 Agent 協助閱讀、修改與驗證程式的開發者。第一版保持單一 admin 管理員、loopback 部署；提供管理員登入，不提供註冊、會員管理、團隊、雲端部署或多層 Agent 編排。

附帶的 [互動原型](ui-prototype.html) 使用虛構資料，無網路請求、不執行指令、不修改專案。可體驗任務切換、送出需求、停止、失敗重試、待答續接，以及成果與活動檢視。重新整理即還原。

## 核心使用流程

1. 首次啟動：管理員登入 → 選工作目錄 → 選模型來源（雲端／本機）→ 檢查設定 → 建立第一個任務。API key 透過本機設定輸入，遮蔽顯示，不進前端持久儲存、事件或 log。沒有設定時顯示可操作的修復提示，保留已填需求。
2. 開始工作：輸入目標。主要畫面只保留任務、對話、活動與成果；模型與權限設定只在首次設定、必要授權或錯誤修復流程中呈現。原型不提供無作用的設定入口或範例按鈕。
3. 執行中：以摘要與工具事件顯示可觀測進度，不顯示或杜撰模型私有推理。允許停止；補充指示依 runtime 能力即時轉交或明示「已排入下一輪」。
4. 等待回答：問題直接出現在對話中，提供回答欄；答案綁定原 task ID。等待輸入與等待授權是不同狀態。
5. 檢視結果：摘要說明改了什麼、驗證結果與限制。右側呈現檔案變更或文字 artifact，可展開原始活動。完成不等於測試通過。
6. 失敗／連線中斷：保留內容與 task ID。結果未知時先查狀態，停用重送；只有確認失敗且使用者選擇重試，才建立新 run。

## 資訊架構與版面

| 區域 | 內容 | 設計理由 |
| --- | --- | --- |
| 左欄，240px | 品牌、新增圖示、任務列表 | 任務是導覽單位；有名稱、文字狀態與選取狀態 |
| 中欄，可伸縮 | 任務標題、工作目錄、對話／活動、底部輸入框 | 保留熟悉的對話，同時讓執行可追蹤 |
| 右欄，320px | 成果、檔案變更、工具詳情、驗證摘要 | 支援使用者查證結果；原始 JSON 放進可展開詳情 |

1440px 一般檢視三欄，成果檢視收起右欄避免重複；1024px 收起右欄為「成果」頁籤；768px 以下任務導覽收為可展開列表，內容單欄。375px 不產生整頁水平捲動；程式碼區獨立水平捲動。桌面優先，手機以追蹤進度與回答問題為主。

## 主要畫面與狀態規格

| 畫面／狀態 | 主要行動 | 必須說清楚的資訊 |
| --- | --- | --- |
| 空工作台 | 建立任務 | 工作目錄、模型設定是否完成 |
| 執行中 | 停止、補充指示 | 目前工具／步驟、已用時間；不編造完成百分比 |
| 待回答 | 回答並繼續 | 原始問題、對應委派 Agent／task |
| 待授權（後續） | 本次允許、拒絕 | 完整命令、目錄、影響範圍；必須有後端 gate 才可啟用 |
| 已完成 | 檢視成果、繼續追問 | 變更摘要、實際測試結果、限制 |
| 已停止 | 建立後續執行 | 停止不回復已寫入檔案，取消請求與已確認取消分開顯示 |
| 失敗 | 查看原因、建立新 run 重試 | 穩定錯誤摘要、可修復步驟、已發生副作用；技術代碼僅在必要詳情中顯示 |
| 結果未知 | 查詢狀態 | 不視為失敗，不自動重送有副作用的請求 |

## 視覺系統

使用 ui-ux-pro-max 的 AI productivity 設計系統搜尋，以及 Developer Tool / IDE 類型搜尋。採用前者的 Flat Design、清楚層級與低動態效果；第二項確認工作台與工具活動方向。搜尋中的行銷頁 hero／影片配置不適用任務工作台，因此不採用。

採用清爽藍白畫布、深墨色文字、柔和藍色主要操作，參考使用者指定的 Meta 藍色方向，並保留原產品識別。橙色只表示需要注意的事項。保持工作內容為視覺中心。原型使用以下經調整的產品 tokens，不直接複製整套搜尋色票：

| Token | 值 | 用途 |
| --- | --- | --- |
| background / surface | #F7F9FC / #FFFFFF | 畫布／內容 |
| text / muted | #1C2B33 / #566779 | 主文／次要資訊 |
| primary / on-primary | #0866D9 / #FFFFFF | 執行與主要行動 |
| border | #E1E7EF | 結構分隔 |
| attention / danger | #92400E / #B42318 | 等待／失敗，均搭配文字 |
| font | Microsoft JhengHei（微軟正黑體）、sans-serif | 本機字型，中文與拉丁文字一致閱讀 |
| spacing / radius | 4、8、12、16、24、32px / 8、12px | 穩定節奏 |

正文 16px、行高 1.6；輔助文字 12–14px。焦點框明顯、桌面按鈕 36px、圖示 18px；觸控版互動目標至少 44px 高、輸入框有簡短提示與供讀屏使用的標籤。Tab 可操作全部互動；Enter 換行，Ctrl／Cmd + Enter 送出。狀態使用 aria-live，動態效果 160ms，尊重 prefers-reduced-motion。正式 UI 需另做螢幕閱讀器與對比驗收。

## 後端對應與缺口

| UI 能力 | 現況依據 | 實作需求 |
| --- | --- | --- |
| 模型與工作目錄 | README、config.py、ModelRef、AgentRun | 本機設定 adapter、連線檢查；不可從前端任意提交可讀寫路徑 |
| 送出與串流活動 | AgentLoopRuntime.run / stream、AgentEvent | 新增本機 UI transport；按 run_id、sequence 整理事件，避免重複 |
| 停止與補充 | runtime.abort / steer / follow_up | 回傳控制結果，區分立即 steering 與排隊；停止需等待結果確認 |
| 任務歷史 | ApplicationService 記憶體 history、SessionStore protocol | 一般對話的持久化實作仍待補齊，不能把 protocol 當成已可恢復 |
| A2A 待答與成果 | docs/a2a.md、現有 SDK client／SQLite | 沿用 task snapshot 判定；一次 session 一個遠端 task，不展示多 Agent 同時編排 |
| 檔案 diff | 工具可讀寫，但沒有完整 UI diff 工作流 | 執行前快照／變更擷取、二進位與大檔策略；不承諾一鍵回復 |
| 逐次命令授權 | 尚未驗證有可用 enforcement | 新增可強制執行的後端攔截；不能只放一個確認按鈕就宣稱安全 |
| token／費用 | 尚未確認完整 usage 資料來源 | 第一版不展示數字；有 provider usage 才顯示實際值，缺資料顯示未知 |

現有 `--shell` 無 sandbox；停用它仍有 `pi_bash` 與寫檔能力。因此不能將「未啟用 shell」標示成「唯讀」或「安全模式」。第一版設定應如實列出可用工具；若需要唯讀，必須由後端確實禁止寫入與指令執行。

## 分期與驗收

第一階段：單工作目錄、單任務執行、模型設定、串流對話、活動詳情、停止、錯誤處理。補上本機 UI transport 與 session 持久化。保留 CLI。

第二階段：檔案 diff、驗證摘要、A2A 原 task 續接與成果檢視。把結果未知、斷線與重啟後失敗納入測試。

正式版第一階段即必須具備 admin 身分驗證與每個對外功能的後端權限檢查。逐次命令授權是不同層級的能力，列為第三階段；再評估多工作目錄。第一版不引入新前端框架；正式框架與打包方式另作選型，原型是零依賴 HTML，不代表正式架構已定案。

驗收目標（待使用者測試驗證）：首次使用者能在 3 分鐘內建立第一個任務；能指出目前執行／待答／失敗狀態；從完成畫面在兩次操作內找到變更與驗證結果；所有核心流程可只用鍵盤完成。必測：缺 key、無效目錄、模型不可用、工具失敗、停止競態、結果未知、頁面重載、375／768／1024／1440px。

## 原型驗證範圍

原型未接真實 Agent；執行、失敗、成果與活動都是示意。它不具備設定儲存、檔案修改、diff 擷取、真正取消或持久化能力。自動結束的短延遲僅供示範，不代表實際執行時間。

## v2 介面精簡

依使用者回饋調整：藍白配色、微軟正黑體優先、移除行銷標語、英文區塊標題、技術實作說明與常駐模型選單。設定與權限的實作需求保留在本提案，不置於主要操作畫面。

新增任務採小型加號；送出／停止共用單一圖示按鈕，依狀態切換。對話、活動、成果保留短標籤搭配一致線條 SVG 圖示；圖示按鈕提供 aria-label 與提示文字。保留任務名稱與文字狀態，避免只能從圖示或顏色猜測。移除空白頁範例按鈕與設定佔位按鈕。

原型僅保留一行「互動預覽」識別。自訂需求完成後顯示預覽結果，不冒充已完成實際工作。

## v3 獨立對抗審查後修正

三位獨立審查專員依 ui-ux-pro-max 檢查視覺、操作流程與無障礙。逐項判斷見 [審查處置紀錄](ui-review.md)。

任務依穩定 ID 保留名稱、選取、草稿、對話、活動、成果、檢視與執行計時器。切換任務不取消工作；僅停止操作取消原型計時器。新增任務會進入列表。資料僅保留於頁面記憶體，重整仍會還原範例。

完成、等待、失敗以圖示與文字區分；失敗時既有按鈕顯示「重試」，不新增常駐控制。訊息允許長字串換行；觸控指標使用至少 44px 命中目標。送出時焦點移到停止，完成時僅當使用者仍停留該控制才回輸入框。手機開啟任務列表時聚焦目前任務，選取後收起並聚焦標題，Escape 可收起。

## 管理員登入與權限邊界

左下角改為「管理員登入」；登入後顯示 admin／管理員及登出圖示。只提供 admin，不設註冊、會員、找回會員密碼或管理員自助建立。未登入時不展示任務、對話與成果，不能送出、停止或新增任務。

此 HTML 為介面預覽，公開示範帳密 admin／pi-demo 僅用於模擬流程；不是認證服務，不可作為正式環境的身分或權限保護。示範身分與密碼不寫入瀏覽器持久儲存，登出清除頁內工作狀態，重整回未登入。

後續所有對外 Agent 功能均須在後端先驗證身分、再驗證該操作及資源的權限。此要求是發布條件，不因本機部署而豁免。詳細範圍及驗收見 [身分與權限需求](security-requirements.md)。
