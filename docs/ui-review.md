# UI 獨立對抗審查與處置

2026-10-26 · 審查範圍：ui-prototype.html、ui-proposal.md

由三位 Agent 分別依 `ui-ux-pro-max` 審查，均未直接修改檔案。主 Agent 逐項核實、判斷與修正。審查依據是原始碼、資料流與 Node DOM 模擬執行，並非真實瀏覽器或讀屏驗收。P1 為工作遺失／主要使用障礙，P2 為流程與可用性問題，P3 為較低優先改善。

| 專員 | 問題 | 判斷與理由 | 對應修正 |
| --- | --- | --- | --- |
| 操作流程 | P1 切換任務取消執行、清除草稿與歷史 | 採納；導覽不應丟失工作 | 每個 task 保存 draft、messages、timer、view；新增任務列入列表 |
| 操作流程 | P2 任務標題、選取與側欄狀態脫節 | 採納；狀態不應取代任務身分 | 使用穩定 ID 選取，名稱獨立於執行狀態，背景完成更新原任務 |
| 操作流程 | P2 待答問題與先前對話消失 | 採納；無法理解續接脈絡 | 儲存雙方 role/text 訊息，狀態轉換只追加紀錄 |
| 視覺 | P2 桌面成果卡片重複 | 採納；沒有額外資訊價值 | 成果檢視收起右欄，中央顯示單一成果 |
| 視覺 | P2 失敗缺少下一步 | 採納；單靠稍後重試不足 | 提示確認服務，既有控制加上「重試」短標籤 |
| 視覺 | P2 提案前文與精簡版本矛盾 | 採納；會誤導後續實作 | 更新主要流程、導覽表與欄位規格 |
| 視覺 | P3 狀態全部同色，掃視辨識弱 | 採納改善，但非「只靠顏色」違規 | 每個狀態加圖示；待答與失敗有輔助色，仍保留文字 |
| 視覺 | P3 預覽識別只有 11px | 採納；無須藉小字降低可讀性 | 改為 12px |
| 無障礙 | P1 長網址與識別碼溢出 | 採納；窄螢幕影響內容閱讀 | 訊息、標題與任務加入 anywhere 換行 |
| 無障礙 | P2 送出後焦點遺失 | 採納；影響連續鍵盤操作 | 執行時聚焦停止；完成僅在焦點仍位於控制時回輸入框 |
| 無障礙 | P2 手機選單焦點順序不合理 | 採納；展開後 Tab 原本跳過任務 | 展開聚焦選取任務；選取後收起並聚焦標題；Escape 返回選單 |
| 無障礙 | P2 讀屏缺少發話者 | 採納；不須增加可見文字 | 每則訊息加發話者 aria-label |
| 無障礙 | P3 平板觸控目標只有 36px | 採納；屬便利性與提案一致性，非宣稱違反 AA 24px 最低要求 | pointer:coarse 使用 44px 目標，圖示維持 18px |
| 無障礙回歸 | P2 背景完成重建列表導致焦點消失 | 採納；會再次打斷鍵盤導覽 | 更新列表前記住 focused task ID，更新後只恢復同一任務按鈕 |

不採取擴張措施：保留現有 button group + aria-pressed，無須增加複雜頁籤鍵盤模式；不加入常駐設定按鈕或增加說明區塊。現有藍白配色、微軟正黑體、圖示可存取名稱與 reduced-motion 規則繼續沿用。

## 驗證與限制

已用 Node DOM 模擬檢查任務草稿往返、執行中切換、背景完成、停止、重試、待答續接、對話保留、輸入跳脫、側欄狀態、完成焦點恢復與不搶焦點、背景更新列表焦點、手機開啟／關閉導覽。HTML ID、selector 與 JavaScript 語法亦已檢查。

主色白字對比約 5.37:1，次要文字與畫布約 5.51:1，選取文字與淡藍底約 4.76:1。這些數值不代表全頁對比或完整 WCAG 認證。

已透過本機 loopback 預覽在真實瀏覽器驗證 375／768／1024／1440px 的頁寬，均未產生水平溢出；視覺檢查涵蓋桌面與 375px 手機。實際操作確認手機選單焦點與收起、待答問題及回答保留、完成後焦點恢復、長網址換行、停止、草稿往返、背景執行，以及成果頁只顯示一張成果卡。另確認實際計算樣式使用藍色 #0866D9 與微軟正黑體優先字型。尚未完成 200% 放大、專用讀屏軟體與實體觸控裝置驗證，不宣稱完整 WCAG 認證。原型仍使用頁面記憶體，重新整理會還原，不接真實 Agent。
